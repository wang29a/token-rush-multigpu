## S1 — The link (2026-10-27, vast-57952342)

Generated by `lab/report_s1.py results/2026-10-27-vast-57952342`. Values below are measured component
results, not model or engine performance. Test-model results do not transfer
to the production model; no model weights were downloaded for S1.

**Machine and version:** 2 x RTX 5090; PCIe Gen5 x16 on both; NODE topology;
400 W caps. PyTorch 2.11.0+cu128, CUDA wheel 12.8, NCCL
2.28.9. Code commit `15314bc51c5f8f95a1044c86594992ac95802c77`;
script SHA-256 `827ab27181644a3ec988964075e9120e12602e26cf2c613c969b45408d68685c`. Full software lock and machine
inventory are adjacent. Runtime-loaded driver libraries are recorded in
`run3/metadata.json`; the image's preconfigured compatibility library was used
without changing the host driver. Date/time boundaries are in UTC in raw JSON;
the experiment date is also 2026-10-27 in Asia/Shanghai.

**Prediction, before the run:** 5–10 us latency proxy, 25–50 GB/s large-message
bandwidth, crossover about 256 KiB. See `prediction.json`. These are preserved
estimates, not retrospectively changed to match measurements.

**What was done:** Two directions, 64 B–256 MiB, single `copy_` and dependent
return `copy_`, eager and one captured cross-device graph; one-GPU-per-process
NCCL broadcast as reference. Seven batches per cell, ten warmups. Small graph
captures unroll 100 operations; large captures unroll four; all normalize by
the actual operation count. CUDA events are on one device's current stream,
including copy stream dependencies; CPU wall times include submission and
completion. Eager timings include Python launch gaps. For broadcast, take the
maximum of the two ranks in each sample, then its median. Byte checks cover
the entire payload, including a changed source value after capture. Timing
uses a repeated buffer; these are component microbenchmarks.

**P2P:** `can_device_access_peer` is false in both directions. NVIDIA's read
and write checks report CNS. The P2P-enabled optimization is unavailable, not
silently represented by a fallback measurement. NCCL INFO logs explicitly
select `SHM/direct/direct` and say P2P is disabled. The exact runtime DMA route
for `copy_` was not separately traced; do not call it a direct peer-memory
measurement merely because the measured bandwidth is high.

**Errors and counterexamples preserved:** run1's naive graph capture failed
with capture isolation, because the peer stream had not been enrolled. An
explicit fork/join fixed this in run2. NCCL graph broadcast then wrote all

destroying the process group. run3 and run4 exit normally for every variant.
run1/run2 are diagnostic artifacts, overlap while teardown stalls, and are
excluded from headline numbers. Their teardown terminations are recorded,
not counted as successful exits.

half-RTT proxy meet <=15 us; the complete graph round trip does not. P2P-on
is unavailable. Therefore S1 data collection is COMPLETE WITH QUALIFICATIONS,
not an unqualified pass. This is a reason to descend to the communication
primitive before any model work, not to replace the RTT by half of it in prose.

## S2 — NCCL baseline (2026-10-27, vast-57952342)

Generated by `lab/report_s2.py results/2026-10-27-vast-57952342/s2`. These are measured
collective components, not model performance. Test-model results do not
transfer to the production model; no model was downloaded or run.

**Question:** Does the P2P-disabled NCCL path fit the latency budget for 128
dependent small SUM all-reduces per token?

**Prediction (written before the run):** graph 10 KiB 12–25 us; eager 16–35 us;
graph 80 KiB 15–35 us. The 128-operation graph: 1.536–3.200 ms at 10 KiB and
1.920–4.480 ms at 80 KiB. Graph improves 10 KiB by 10–40%, and normalized
chain latency differs from isolated graph latency by <=25%. Large-message
algorithmic bandwidth 15–45 GB/s. These estimates and the separate bounded
check predictions are preserved in `prediction.json` and
`bounded-check-prediction.json`, written before their respective runs.

**Machine/version/code:** same 2 x RTX 5090, Gen5 x16, NODE, 400 W box as S1.
Runtime peer access false both directions. PyTorch 2.11.0+cu128, CUDA wheel
12.8, NCCL 2.28.9. Code commit
`69cfc236db2a037016604e2186c4c070b768391c`; SHA-256 `8b2f7f76fca4a0941379df110b94dd64eb7e63c681d762bc6dea9ed7ee468909`. Every run records
parameters, UUIDs, topology, loaded CUDA libraries, code/helper hashes and
NCCL environment. Raw dates are UTC; the date is 2026-10-27 in Asia/Shanghai.

**What was done:** SUM all-reduce, all-gather, SUM reduce-scatter and broadcast
from either rank, two GPUs, one GPU per process. BF16 payloads 10/80 KiB,
1/64 MiB. `graph1` captures one operation; `graph128` captures 128 dependent
in-place SUM operations on the same tensor, for 10/80 KiB. Nine timing
batches, 20 warmups; 100 replays per small single-operation batch, 10 per
large batch, five per 128-chain batch. GPU events include the NCCL internal
stream completion edge; wall timing includes enqueue and completion. The
reported statistic takes max(rank) for each sample, then its median.

**Correctness:** complete nonuniform rank-specific patterns checked before
and after timing, with a different fresh pattern after capture. Timed SUM
inputs are zero to avoid repeated doubling overflow; SUM is still executed.
For a single correctness replay of graph128, inputs are scaled by 2^-120;
the exact expected final factor is 384, so every intermediate and final
BF16 value stays finite. Non-finite or incorrect values fail the worker.

**Bottleneck:** the default 10 KiB isolated graph is 9.391 us, but
the dependent chain is 14.309 us/op (1.832 ms/128),
52.4% above the isolated result. The repeat is 14.369 us/op
(+0.42%). NCCL INFO explicitly reports SHM/direct/direct;
P2P is disabled. Ring/LL does not remove the serial-chain cost; Tree/LL and
Ring/Simple are slower. This bounds what these configuration levers buy on
this code path. The extra cost is NOT proven to be pure link latency: graph
event/stream scheduling and transport behavior have not been separately
isolated. A communication-only chain also omits compute/communication
interactions present in a model.

**Prediction vs result:** isolated 10 KiB 9.391 us is below the
12–25 us range; 80 KiB 12.887 us is below
15–35 us. The predicted 128-chain ranges hold. Graph's 10 KiB gain is
47.4%, above the predicted 10–40%. The <=25% normalized-chain agreement
prediction is REFUTED by 52.4%. 64 MiB all-reduce achieves
28.04
GB/s algorithmic bandwidth, within the predicted 15–45 GB/s.

The bounded check predicted default repeat 11.45–17.17 us, Ring/LL 8–15 us,
Tree/LL 8–15 us, Ring/Simple 15–30 us for the 10 KiB chain. All fit their
ranges EXCEPT Tree/LL, which misses above 15 us. No tested chain profile
meets <=12 us, so the preregistered candidate-confirmation rule is not
triggered and the sweep stops here. Every configuration is reported;
none of these diagnostic environment overrides is persisted globally.

132.2 tok/s, approximately 1.31x the

Phase 4, 2026-09-09/10. The calculation does not justify a 1.5x engine claim.

**Gate and decision:** NCCL baseline data collection is COMPLETE. Isolated

Do not select the isolated result and declare M0 clear. Full M0 remains
